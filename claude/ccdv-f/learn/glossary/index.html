    Glossary

    Plain-English definitions of the 77 key terms in the CCDV-F learning guide, each linked to the lessons that teach it.

    Written and maintained by Prakash Sridharan, Claude Certified Architect

    ABCEFGHILMOPRSTVW

    A

    Agent

    A system in which a model uses tools in a loop to reach a goal, choosing its own next steps instead of following a fixed path set in code.

    Also: agents, AI agent

    Lessons 1.1 Choosing a Workflow, an Agent and a Runtime1.2 Building Agents with the Agent SDK and Hooks1.3 Diagnosing a Misbehaving Agent

    Agentic loop

    The cycle an agent runs: Claude replies, the code runs any tools it asked for, the results go back, and this repeats until Claude ends its turn or a limit is reached.

    Also: agent loop

    Lesson 1.2 Building Agents with the Agent SDK and Hooks

    Amazon Bedrock

    AWS's managed service for foundation models, through which Claude can be used inside an AWS account.

    Also: Bedrock

    Lesson 2.2 The Application Boundary

    Audit log

    A record of who did what and when, including an agent's actions and tool calls, kept for review, compliance and investigating incidents.

    Also: audit logs, audit trail

    Lessons 1.1 Choosing a Workflow, an Agent and a Runtime1.2 Building Agents with the Agent SDK and Hooks

    B

    Bias

    A systematic skew in output, such as favoring certain groups, viewpoints or answer positions. Found by testing varied inputs and reviewing the results.

    Also: biased

    Lesson 4.1 Designing Evaluations That Measure the Goal

    C

    Chunking

    Splitting documents into smaller passages for indexing and retrieval. Chunk size and where the boundaries fall decide what retrieval can find.

    Also: chunk, chunks

    Lesson 6.4 Grounding Answers and Citing Sources

    Circuit breaker

    A safeguard that stops calling a failing tool or service after repeated errors, so the system fails fast instead of piling up retries.

    Also: circuit breakers

    Lesson 2.4 Resilient Integrations: Errors, Streams and Files

    Citations

    References from Claude's answer to the exact source passages behind it, so a reader can check each claim.

    Also: citation, cite sources

    Lessons 2.2 The Application Boundary4.1 Designing Evaluations That Measure the Goal6.4 Grounding Answers and Citing Sources

    Claude Agent SDK

    Anthropic's library, for Python and TypeScript, for building agents on the same agent loop, tools and context management that power Claude Code.

    Also: Agent SDK

    Lessons 1.1 Choosing a Workflow, an Agent and a Runtime1.2 Building Agents with the Agent SDK and Hooks8.2 Building and Integrating MCP Servers

    Claude Code

    Anthropic's agentic coding tool. It reads code, edits files and runs commands, in the terminal, an IDE, the desktop app or the browser.

    Lessons 1.2 Building Agents with the Agent SDK and Hooks3.1 Operating Claude Code8.2 Building and Integrating MCP Servers

    Claude Managed Agents

    Anthropic's hosted service that runs agents in a managed sandbox, with sessions and events, so you do not have to build and operate the agent loop yourself.

    Also: Managed Agents

    Lessons 1.1 Choosing a Workflow, an Agent and a Runtime2.2 The Application Boundary

    CLAUDE.md

    A Markdown file that Claude Code loads at the start of a session, holding instructions such as build commands and coding conventions. It can be set for the user, the project or a single directory.

    Lessons 2.3 Configuration Across Environments and CI3.1 Operating Claude Code3.2 Extending Claude Code for a Team

    Code execution tool

    A tool that lets Claude run code in a sandbox to analyze data, do calculations and create files.

    Also: code execution

    Lessons 1.1 Choosing a Workflow, an Agent and a Runtime5.1 Tokens, Sampling, Thinking and Effort8.3 Choosing Tools, Skills or MCP

    Compaction

    Summarizing the earlier part of a long conversation to free space in the context window while keeping the facts still needed.

    Also: compact, auto-compact

    Lessons 1.3 Diagnosing a Misbehaving Agent3.1 Operating Claude Code6.1 Keeping Long Sessions on Track

    Confidence calibration

    How well a stated confidence matches real accuracy. Well-calibrated scores can be used to send low-confidence cases to a person.

    Also: calibration, calibrated, well-calibrated

    Lesson 4.1 Designing Evaluations That Measure the Goal

    Context window

    The maximum amount of text, counted in tokens, that a model can consider in one request: the system prompt, the conversation so far, tool definitions and results, and its own reply. Whatever does not fit is not seen.

    Also: context length

    Lessons 1.1 Choosing a Workflow, an Agent and a Runtime1.3 Diagnosing a Misbehaving Agent3.1 Operating Claude Code

    E

    Embedding

    A list of numbers that represents the meaning of a text, so texts with similar meaning have nearby embeddings. Used for semantic search.

    Also: embeddings

    Lesson 6.4 Grounding Answers and Citing Sources

    Escalation

    Routing a case from the automated system to a person, triggered by rules such as low confidence, high value, a policy exception or the customer asking for one.

    Also: escalate, escalated, escalates

    Lessons 3.1 Operating Claude Code5.2 Choosing a Model Tier and Planning Upgrades5.3 Finding and Fixing the Cost Driver

    Evaluation (eval)

    A repeatable test of a model, prompt or agent against a set of cases with expected outcomes, scored by code, by people or by a model. Used to compare versions and catch regressions.

    Also: eval, evals, evaluation, evaluations

    Lessons 4.1 Designing Evaluations That Measure the Goal5.2 Choosing a Model Tier and Planning Upgrades6.2 Revising a Prompt That Evaluations Flag

    Exponential backoff

    Waiting longer after each failed attempt before retrying, usually with some random jitter, so retries do not overload the service.

    Also: backoff, retry with backoff

    Lessons 2.1 Messages API Mechanics2.4 Resilient Integrations: Errors, Streams and Files

    Extended thinking

    A mode in which Claude reasons step by step in thinking blocks before giving its final answer, within a token budget. It helps on complex, multi-step problems at the cost of extra tokens and time.

    Also: thinking budget, thinking blocks

    Lessons 1.2 Building Agents with the Agent SDK and Hooks2.1 Messages API Mechanics5.1 Tokens, Sampling, Thinking and Effort

    F

    Files API

    Uploading a file once and referring to it by its ID in later requests, instead of sending its content every time.

    Lessons 2.1 Messages API Mechanics2.4 Resilient Integrations: Errors, Streams and Files8.2 Building and Integrating MCP Servers

    G

    Golden dataset

    A curated set of test cases with known correct answers that evaluations are scored against.

    Also: golden set, gold set, ground truth

    Lesson 4.1 Designing Evaluations That Measure the Goal

    Grounding

    Telling Claude to base its answer only on material you supply, and to say plainly when that material does not cover the question.

    Also: grounded

    Lessons 4.1 Designing Evaluations That Measure the Goal4.2 Diagnosing Failure Modes from Traces6.4 Grounding Answers and Citing Sources

    Guardrail

    A check outside the model's own judgment that blocks or corrects unsafe or invalid actions, such as input validation, an allow list or a hook.

    Also: guardrails

    Lessons 3.2 Extending Claude Code for a Team7.2 Deterministic Guardrails and Least Privilege

    H

    Hallucination

    A confident statement that is not supported by the source material or by fact. Reduced by grounding answers in supplied documents, asking for quotes or citations, and allowing the answer "I don't know".

    Also: hallucinate, hallucinated

    Lessons 4.2 Diagnosing Failure Modes from Traces6.4 Grounding Answers and Citing Sources7.1 Defending Against Prompt Injection

    Handoff

    Passing a task, together with the context needed to continue it, from one agent to another or from an agent to a person.

    Also: handoffs, hand off

    Lesson 1.1 Choosing a Workflow, an Agent and a Runtime

    Headless mode

    Running Claude Code without the interactive session, using the -p flag, for scripts and CI pipelines. Output can be plain text or JSON.

    Lessons 1.2 Building Agents with the Agent SDK and Hooks2.3 Configuration Across Environments and CI3.1 Operating Claude Code

    Hook

    A command that runs automatically at a set point in an agent's lifecycle, for example before a tool call (PreToolUse) or after it (PostToolUse). Unlike an instruction in a prompt, a hook always runs.

    Also: hooks, PreToolUse, PostToolUse

    Lessons 1.2 Building Agents with the Agent SDK and Hooks3.2 Extending Claude Code for a Team7.2 Deterministic Guardrails and Least Privilege

    Human in the loop (HITL)

    A design in which a person reviews or approves certain actions or outputs before they take effect, usually the high-impact or low-confidence ones.

    Also: human-in-the-loop, HITL, human review, human approval

    Lessons 4.1 Designing Evaluations That Measure the Goal7.2 Deterministic Guardrails and Least Privilege

    Hybrid search

    Combining keyword search, such as BM25, with embedding search, so both exact terms like product codes and differently worded passages are found.

    Also: BM25

    Lesson 6.4 Grounding Answers and Citing Sources

    I

    Idempotency

    The property that doing an operation twice has the same effect as doing it once. An idempotency key lets an agent retry a write, such as a payment, without making it twice.

    Also: idempotent, idempotency key, idempotency keys

    Lessons 1.3 Diagnosing a Misbehaving Agent8.1 Designing Tools and Shaping Their Results

    Iteration

    Improving a prompt or an output over several rounds, changing one thing at a time and checking the effect of each change.

    Also: iterate, iterating, iterative

    Lesson 1.2 Building Agents with the Agent SDK and Hooks

    L

    Latency

    The time between sending a request and getting the response. For chat, the time to the first token matters most.

    Also: time to first token, TTFT

    Lessons 1.1 Choosing a Workflow, an Agent and a Runtime5.2 Choosing a Model Tier and Planning Upgrades6.4 Grounding Answers and Citing Sources

    Least privilege

    Giving an agent or tool only the permissions its task needs, which limits the damage a mistake or an attack can do.

    Also: least-privilege

    Lessons 7.1 Defending Against Prompt Injection7.2 Deterministic Guardrails and Least Privilege

    LLM as a judge

    Using a model to grade another model's outputs against a rubric. Its grades need checking against human ones, because judges have biases such as preferring longer answers or the first answer shown.

    Also: LLM-as-judge, LLM judge, LLM-as-a-judge, model-graded

    Lesson 4.1 Designing Evaluations That Measure the Goal

    M

    MCP connector

    A Messages API feature that connects a request to remote MCP servers directly, without running your own MCP client.

    Lesson 8.2 Building and Integrating MCP Servers

    MCP server

    A program that offers tools, resources or prompts over MCP, for example in front of a database, a file system or a business application.

    Also: MCP servers

    Lessons 7.2 Deterministic Guardrails and Least Privilege8.2 Building and Integrating MCP Servers8.3 Choosing Tools, Skills or MCP

    MCP transport

    How an MCP client and server exchange messages: stdio for a server running as a local process, Streamable HTTP for a remote server.

    Lesson 8.2 Building and Integrating MCP Servers

    Memory tool

    A tool that lets Claude save and read information in files outside its context window, so knowledge can carry over between sessions.

    Lesson 1.3 Diagnosing a Misbehaving Agent

    Message Batches API

    An API for submitting large groups of requests that are processed asynchronously, usually within 24 hours, at half the normal price. Suited to work that does not need an answer straight away.

    Also: Batch API, batch processing, Message Batches

    Lessons 1.1 Choosing a Workflow, an Agent and a Runtime2.1 Messages API Mechanics5.3 Finding and Fixing the Cost Driver

    Messages API

    The main Claude API: you send a conversation as a list of user and assistant messages, plus optional system prompt and tools, and receive the next assistant message.

    Lessons 1.2 Building Agents with the Agent SDK and Hooks2.2 The Application Boundary7.3 Handling API Keys and Credentials

    Model Context Protocol (MCP)

    An open standard for connecting AI applications to tools and data. An MCP server offers tools, resources and prompts; an MCP client inside the application connects to it.

    Also: MCP

    Lessons 1.2 Building Agents with the Agent SDK and Hooks8.2 Building and Integrating MCP Servers8.3 Choosing Tools, Skills or MCP

    Model migration

    Moving an application to a newer model: rerunning evaluations, adjusting prompts and settings, and rolling the change out gradually.

    Also: migrating to a new model, model upgrade

    Lessons 2.3 Configuration Across Environments and CI4.2 Diagnosing Failure Modes from Traces

    O

    Observability

    Being able to see what a system is doing from its traces, logs and metrics, such as each model call, tool call, delay and cost in an agent run.

    Also: tracing, traces

    Lessons 1.3 Diagnosing a Misbehaving Agent4.2 Diagnosing Failure Modes from Traces6.1 Keeping Long Sessions on Track

    Orchestrator

    The agent or code that splits a task, hands the parts to workers or subagents and combines what they return.

    Also: coordinator, lead agent, orchestrator-workers

    Lessons 1.1 Choosing a Workflow, an Agent and a Runtime1.3 Diagnosing a Misbehaving Agent

    P

    Permission mode

    The Claude Code setting for how much Claude may do without asking, from asking before every edit or command to accepting edits automatically. Plan mode is one of the modes.

    Also: permission modes

    Lesson 3.1 Operating Claude Code

    PII

    Information that can identify a person, such as a name, address, ID number or health record. Often removed or masked before text reaches a model or a log.

    Also: personally identifiable information, personal data

    Lesson 2.2 The Application Boundary

    Plan mode

    A Claude Code mode in which Claude explores the code and proposes a plan without editing files, so you can review the approach before any change is made.

    Lesson 3.1 Operating Claude Code

    Plugin

    A package that bundles Claude Code extensions, such as skills, subagents, hooks and MCP servers, so a team can install them together.

    Also: plugins

    Lessons 2.3 Configuration Across Environments and CI3.2 Extending Claude Code for a Team8.2 Building and Integrating MCP Servers

    Plugin marketplace

    A catalog, usually a repository with a marketplace file, from which users find and install plugins.

    Also: marketplace

    Lesson 3.2 Extending Claude Code for a Team

    Precision and recall

    Precision is the share of flagged items that really are positive; recall is the share of real positives that were flagged. Raising one usually lowers the other.

    Lessons 4.1 Designing Evaluations That Measure the Goal6.4 Grounding Answers and Citing Sources

    Prefilling

    Writing the start of Claude's reply yourself, as an assistant message it continues, to fix the format, for example starting with an opening brace for JSON.

    Also: prefill, prefilled

    Lesson 2.1 Messages API Mechanics

    Prompt caching

    Reusing the processed form of a repeated prompt prefix, such as long instructions or a reference document, across requests. Cached reads cost much less and return faster, but only an exact match of the prefix up to the cache breakpoint is reused.

    Also: cache breakpoint, cache_control

    Lessons 2.1 Messages API Mechanics5.3 Finding and Fixing the Cost Driver6.4 Grounding Answers and Citing Sources

    Prompt chaining

    Splitting a task into a sequence of prompts in which each step's output feeds the next, so every step stays simple and can be checked on its own.

    Also: chained prompts

    Lesson 1.1 Choosing a Workflow, an Agent and a Runtime

    Prompt injection

    An attack in which instructions hidden in content the model reads, such as a web page, email, document or tool result, try to make it act against its user or developer.

    Also: indirect prompt injection, injection

    Lesson 7.1 Defending Against Prompt Injection

    Prompt template

    A reusable prompt with fixed instructions and placeholders for the parts that change, so a team gets consistent results from the same kind of request.

    Also: prompt templates, template, templates

    Lessons 6.2 Revising a Prompt That Evaluations Flag8.2 Building and Integrating MCP Servers

    R

    Rate limit

    A cap on requests or tokens per minute for an organization. Going over it returns HTTP 429, which a client should handle by waiting and retrying with backoff.

    Also: rate limits, HTTP 429, 429

    Lessons 2.4 Resilient Integrations: Errors, Streams and Files4.2 Diagnosing Failure Modes from Traces7.3 Handling API Keys and Credentials

    Regression testing

    Running an evaluation suite again after a change, such as a new prompt, model or tool, to confirm that what worked before still works.

    Also: regression test, regression tests, regression suite

    Lessons 4.1 Designing Evaluations That Measure the Goal5.2 Choosing a Model Tier and Planning Upgrades

    Reranking

    A second pass that reorders retrieved candidates by relevance, usually with a stronger model, so only the best few go into the prompt.

    Also: reranker, rerank

    Lesson 6.4 Grounding Answers and Citing Sources

    S

    Sandboxing

    Running commands in an isolated environment with limits on file system and network access, so an agent can act with fewer approval prompts at lower risk.

    Also: sandbox, sandboxed

    Lessons 1.1 Choosing a Workflow, an Agent and a Runtime7.1 Defending Against Prompt Injection7.2 Deterministic Guardrails and Least Privilege

    settings.json

    Claude Code's configuration file, at user, project and local level, for permissions, hooks, environment variables and other options.

    Lessons 2.3 Configuration Across Environments and CI3.1 Operating Claude Code

    Skill

    A folder with a SKILL.md file of instructions, plus optional scripts and resources, that Claude loads only when a task needs it. Skills work in Claude Code, the API and claude.ai.

    Also: skills, Agent Skills, SKILL.md

    Lessons 1.2 Building Agents with the Agent SDK and Hooks3.2 Extending Claude Code for a Team8.3 Choosing Tools, Skills or MCP

    Slash command

    A command typed as /name in Claude Code. Built-in commands control the session; custom ones run saved prompts.

    Also: slash commands, custom command, custom commands

    Lesson 8.2 Building and Integrating MCP Servers

    Stop reason

    The field in an API response that says why generation ended, for example end_turn, max_tokens, stop_sequence or tool_use. An agent loop reads it to decide whether to run a tool or finish.

    Also: stop_reason, end_turn

    Lessons 1.2 Building Agents with the Agent SDK and Hooks2.1 Messages API Mechanics2.4 Resilient Integrations: Errors, Streams and Files

    Streaming

    Receiving a response in pieces, as server-sent events, while it is being generated, so users see output at once instead of waiting for the whole message.

    Lessons 2.1 Messages API Mechanics2.4 Resilient Integrations: Errors, Streams and Files3.1 Operating Claude Code

    Structured outputs

    Constraining a response to a given JSON schema so code can parse it reliably. A tool with an input schema can be used the same way.

    Also: structured output

    Lessons 2.1 Messages API Mechanics4.2 Diagnosing Failure Modes from Traces6.3 Structured Output and Defensive Parsing

    Subagent

    An agent started by another agent to handle one subtask in its own context window. It returns only its result, which keeps the parent's context small.

    Also: subagents, sub-agent

    Lessons 1.1 Choosing a Workflow, an Agent and a Runtime1.3 Diagnosing a Misbehaving Agent3.2 Extending Claude Code for a Team

    System prompt

    Instructions sent separately from the conversation that set Claude's role, rules and background for every turn of it.

    Also: system prompts

    Lessons 2.2 The Application Boundary5.3 Finding and Fixing the Cost Driver6.2 Revising a Prompt That Evaluations Flag

    T

    Temperature

    A sampling setting that controls randomness: lower values give more predictable wording, higher values more varied wording. It does not make answers more accurate.

    Lessons 1.2 Building Agents with the Agent SDK and Hooks5.1 Tokens, Sampling, Thinking and Effort6.4 Grounding Answers and Citing Sources

    Token

    The unit models read and write text in, on average a little less than one English word. Context windows, rate limits and prices are all counted in tokens.

    Also: tokens

    Lessons 5.1 Tokens, Sampling, Thinking and Effort5.3 Finding and Fixing the Cost Driver8.2 Building and Integrating MCP Servers

    Tool result

    The message that returns a tool's output to Claude, matched to the request by its ID. Marking it as an error lets Claude see that the call failed and recover.

    Also: tool_result, is_error

    Lessons 1.2 Building Agents with the Agent SDK and Hooks1.3 Diagnosing a Misbehaving Agent2.2 The Application Boundary

    Tool use

    Letting Claude call functions you define. Claude returns a tool_use request with arguments, your code runs the tool, and you send the output back as a tool result.

    Also: function calling, tool call, tool calls, tool calling

    Lessons 1.2 Building Agents with the Agent SDK and Hooks3.1 Operating Claude Code5.2 Choosing a Model Tier and Planning Upgrades

    tool_choice

    An API setting that lets Claude decide whether to use a tool (auto), requires it to use one (any), forces a named tool, or turns tools off (none).

    Lessons 2.1 Messages API Mechanics8.1 Designing Tools and Shaping Their Results

    V

    Verification

    Checking AI output against a trusted reference before it is used, such as the source documents, known data or an expert, with more checking where the stakes are higher.

    Also: verify, verified, fact-check, fact-checking

    Lessons 1.3 Diagnosing a Misbehaving Agent4.2 Diagnosing Failure Modes from Traces6.4 Grounding Answers and Citing Sources

    Vertex AI

    Google Cloud's AI platform, through which Claude can be used inside a Google Cloud project.

    Also: Google Vertex AI, Google Cloud Vertex AI

    Lessons 2.2 The Application Boundary5.2 Choosing a Model Tier and Planning Upgrades

    W

    Workload identity federation

    Letting a workload authenticate with short-lived credentials from its own cloud identity provider instead of a long-lived API key stored with it.

    Lesson 7.3 Handling API Keys and Credentials
