    Choosing Tools, Skills or MCP

    Exam skillCapability Mechanism Selection

    Evaluating built-in tools, custom tools, Skills, and MCP servers for a use case, based on where the capability must live, who maintains it, and how Claude discovers and invokes it, and justifying the selection.

    Choose between built-in tools, custom tools, Skills and MCP servers by asking where the capability must live, who maintains it and how Claude discovers and invokes it, and justify the choice against simpler alternatives.

    Written and maintained by Prakash Sridharan, Claude Certified Architect

    On this pageWhat you need to knowIn the examCheck your understandingApply itSources

    What you need to know

    The four mechanisms

    MechanismWhat it isLives and runsMaintained byHow Claude finds it
    Built-in (server) toolsWeb search, web fetch, code execution and othersAnthropic's sideAnthropicEnabled in the request
    Custom (client) toolsYour function with a schemaYour applicationThe app's teamTool definitions in the request
    SkillsFolders of instructions, scripts and resourcesLoaded into Claude's context when relevant (Claude Code, API, Agent SDK)Whoever owns the procedureName and description; body loads on demand
    MCP serversA service exposing tools, resources and prompts over a standard protocolSeparately hosted (local or remote)The system's ownersThe client lists the server's capabilities

    Decision questions

    1. Does a built-in tool already do it? Web search, code execution: enable it, do not rebuild it.
    2. Is it know-how or an action? Procedures, style rules and checklists are Skills. Actions on systems are tools.
    3. Who needs it? One app: a custom tool defined in that app. Many clients (an agent, Claude Code, other apps): an MCP server maintained by the system's owners.
    4. Must the result be exact? Deterministic logic (a tax formula) belongs in code exposed as a tool, not described in a Skill or prompt.
    5. Where must secrets live? Never in a Skill or prompt; in the tool's or server's own environment.
    Decision rule
    The simplest mechanism that fits

    An MCP server for a capability used by one script and maintained by one person adds hosting and upkeep for nothing. A Skill containing a database password is a leak. Match the mechanism to where the capability lives and who owns it.

    Combining them

    Mechanisms work together. A release Skill can describe the steps and call an MCP tool for the issue tracker and a small custom script for date conversion. Built-in code execution can run the scripts a Skill bundles.

    Example
    One company, three needs

    A deployment checklist: Skill. The company issue tracker used from several tools: MCP server. Converting dates inside one script: plain code or a small custom tool.

    Exam trap
    MCP for everything

    MCP's value is reuse across clients and separate ownership. Without those, a custom tool is simpler.

    In the exam

    Items describe a capability, who needs it and who maintains it, and ask which mechanism fits or why a choice is wrong. Prefer built-in tools when they exist, Skills for know-how, custom tools for one app's actions, MCP for shared systems, and code for exact logic. Distractors put secrets in Skills, rebuild built-in tools, or stand up servers for single-consumer helpers.

    Check your understanding

    Question 1

    A Messages API app needs recent public news with the least work. Which mechanism?

    Show answer

    Answer: A. Built-in tools need only to be enabled.

    Question 2

    Only one chat app needs to look up a customer's open orders. Which mechanism?

    Show answer

    Answer: B. One consumer, one owner: a custom tool is simplest.

    Question 3

    A tax formula must be computed exactly the same way every time. Which mechanism?

    Show answer

    Answer: D. Code gives exact, repeatable results.

    Apply it: Choose mechanisms for Quarry Lane

    Exercise · about 15 minCase: Quarry Lane Software

    Quarry Lane's needs: (A) the help assistant must search the public web for third-party integration notices; (B) engineers want Claude to follow the release-notes procedure; (C) the internal docs system should be usable from Claude Code, the help assistant's backend and a Slack bot; (D) the help assistant must compute subscription proration exactly; (E) a one-off script needs to format dates.

    1. Choose a mechanism for each need.
    2. Justify each by where it lives and who maintains it.
      Done when: no choice is heavier than the need.
    Check your work
    Show model answer

    A. Built-in web search tool: Anthropic runs it; just enable it (with allowed domains).

    B. A Skill in the team plugin: procedural know-how, maintained by the release owners, loaded when release notes are requested.

    C. An MCP server over HTTP with OAuth: three clients share it, and the docs team maintains it.

    D. A custom tool in the help assistant's backend that computes proration in code: exact, and only that app needs it.

    E. Plain code in the script, no Claude mechanism needed.
