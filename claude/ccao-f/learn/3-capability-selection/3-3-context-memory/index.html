    Managing Context and Memory

    Exam skillContext and Memory Management

    Applying context and memory management to long or multi-session work, including when to restart, summarize, persist to a Project, or rely on memory, and maintaining memory quality through review, edits, deletions, and incognito chats.

    Context is a budget. Restart from a summary when a long chat drifts, persist stable decisions to a Project, rely on memory only for recurring facts, keep memory accurate by reviewing and deleting entries, and use incognito chats for conversations that should stay out of history and memory.

    Written and maintained by Prakash Sridharan, Claude Certified Architect

    On this pageWhat you need to knowIn the examCheck your understandingApply itSources

    What you need to know

    Every conversation has a working-memory limit. As a long chat approaches it, earlier messages are summarized to make room, and detailed instructions given early can lose force. Managing context is choosing deliberately among four moves.

    Restart, summarize, persist or rely on memory

    MoveWhenHow
    RestartA long chat has drifted, or a genuinely new task beginsNew chat; Project instructions and knowledge carry over, the old thread does not
    SummarizeThe thread holds decisions worth keepingAsk for decisions, work in progress and open questions; start the new chat with that summary
    PersistInformation every future chat needsRules in Project instructions, facts and decisions in Project knowledge
    MemoryRecurring facts about you and your workLet memory carry role, preferences, recurring context

    Chats in the same Project share its instructions and knowledge, but not each other's threads.

    Example
    Drift, not disobedience

    A teacher's rule "no student devices" held all morning and slipped after two hours. The fix is a fresh chat with the rules summarized, or the rule in Project instructions, not repeating it in the same long chat.

    Keep memory accurate

    Memory is useful only if it is current. Treat it like a working file:

    • Review stored memories regularly.
    • Edit or delete entries that no longer hold (a contact who left, last year's budget).
    • Scope memory: separate Projects keep project-scoped memory apart, so one client's context does not appear in another's work.
    • Reset after backing up what matters when stale entries are too many to fix one by one.

    Incognito chats

    Incognito chats are kept out of chat history and memory and do not use existing memory. They suit exploratory or sensitive conversations outside Projects. They are still retained for a period under the default or the organization's retention settings and can appear in organizational exports. Incognito decides what is remembered, not whether data may be shared.

    Exam trap
    Memory as a rulebook

    Memory is best effort and per user. Firm rules belong in Project instructions, documents in knowledge, procedures in Skills.

    In the exam

    Items describe drift in a long chat, re-explaining across sessions, stale or leaking memory, or a sensitive one-off chat. Choose restart with summary, persist to a Project, edit or scope memory, or incognito. Distractors keep one endless chat, repeat reminders, turn memory off permanently, or treat incognito as making data safe.

    Check your understanding

    Question 1

    A long planning chat has drifted but holds many decisions. Best way to continue?

    Show answer

    Answer: B. A summary carries continuity without the degraded context.

    Question 2

    Memory still names a client contact who left three months ago. What should happen?

    Show answer

    Answer: C. Stale entries should be corrected, and regular review catches them.

    Question 3

    A user believes an incognito chat leaves no record anywhere. What is accurate?

    Show answer

    Answer: A. Incognito controls history and memory, not all retention.

    Apply it: Organize Brightwater's context

    Exercise · about 15 minCase: Brightwater Communications

    An account executive serves both competing grocery clients from one Project. Memory has started surfacing one client's promotions in the other's drafts. She also works in a single, months-long chat per client, and Claude now ignores the brand rules she set at the start.

    1. Restructure the setup to stop the leakage.
    2. Fix the long-chat drift.
    3. Set a memory routine.
      Done when: no client context can cross over and rules no longer fade.
    Check your work
    Show model answer

    1. One Project per client, each with its own instructions (brand rules), knowledge (brand guide, current campaigns) and project-scoped memory. Delete the cross-client memory entries from the old Project, then retire it.

    2. Move the brand rules into each Project's instructions so every chat has them. Ask each long chat for a summary of open decisions and campaign status, then continue in fresh chats inside the right Project.

    3. Review each Project's memory monthly and after every campaign ends; delete expired promotions and departed contacts.
