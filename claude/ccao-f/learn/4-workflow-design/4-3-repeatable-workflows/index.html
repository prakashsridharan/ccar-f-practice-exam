    Designing Repeatable Workflows

    Exam skillRepeatable Workflow Design

    Applying repeatable-workflow design to a recurring task currently done manually or with unstructured prompting, including Projects, Skills, connectors, code-executed steps, consistency across runs and users, and workflows handed off to a colleague who owns them afterward.

    Turn a recurring, manual or unstructured task into a workflow anyone can run the same way. Put shared context in a Project, procedures in Skills, live data behind connectors, and numbers in code-executed steps. Prove the gain, measure it, and hand it off with an owner and documentation.

    Written and maintained by Prakash Sridharan, Claude Certified Architect

    On this pageWhat you need to knowIn the examCheck your understandingApply itSources

    What you need to know

    "I use Claude" is a personal habit. "Our workflow uses Claude" is a process that gives the same quality whoever runs it. The signal that a task is ready: it recurs, its context is stable, and its output format is consistent.

    Find the friction

    Watch one full cycle and note every manual step you also did last time:

    SignalFix
    Repetition: the same background pasted every runProject knowledge or instructions
    Correction: the same flaw fixed in every outputA configuration change, often an instruction or a Skill
    Variance: different people get different resultsA shared Project and shared Skills
    Manual data copyingA connector to the live source
    Hand or prose arithmeticA code-executed step
    Decision rule
    Rule, reference or procedure?

    A rule that always applies goes in instructions. Reference material every run needs goes in knowledge. A multi-step procedure goes in a Skill. Putting a fix in the wrong home is why some optimizations do not stick.

    Prove it, then measure it

    Run the new setup alongside the old approach for a few cycles before relying on it: a defect baked into a shared workflow spreads to everyone. Measure what mattered, such as time per cycle, revision rounds and consistency across people.

    Hand-off to a new owner

    A workflow outlives its builder only if:

    • It lives where the owner can reach and edit it: a shared Project and shared Skills, not a personal account or chat history.
    • It is documented: purpose, inputs, steps, what is checked and by whom, and who to escalate to.
    • The logic is explained, especially what each Skill does and why.
    • The new owner has run it once under supervision.
    • Shared configuration has one owner who approves changes, so one person's preferences do not change everyone's output.
    Exam trap
    Sharing a personal setup unchanged

    A Project tuned for one teacher's class, or one analyst's habits, often carries assumptions that do not fit colleagues. Generalize it before sharing.

    In the exam

    Items describe a recurring task done inconsistently or by hand, a hand-off, or a newly optimized workflow. Choose shared configuration, the right home for each fix, connectors and code execution for data steps, a side-by-side trial, and documentation with an owner. Distractors ask people to write better personal prompts, rely on memory, keep the workflow in one person's account, or count Skills as a measure of success.

    Check your understanding

    Question 1

    Four analysts produce the same monthly summary with their own prompts, and formats differ. Best fix?

    Show answer

    Answer: C. Shared configuration brings consistency across users.

    Question 2

    A builder of a Claude workflow is leaving. What matters most for the hand-off?

    Show answer

    Answer: D. The owner needs access to the setup and to how it is run and verified.

    Question 3

    A new Skill made outputs more consistent but one section less accurate. What should have been done?

    Show answer

    Answer: C. Proving the gain before relying on it catches regressions.

    Apply it: Make Ironwood's weekly report repeatable

    Exercise · about 25 minCase: Ironwood Logistics

    Six site managers each produce the weekly operations report their own way, and the VP spends 90 minutes reconciling them. Data lives in Google Sheets updated every Monday. Next quarter, the regional analyst, Maya Chen, will own the workflow.

    1. List the frictions and the home for each fix.
    2. Describe the repeatable workflow.
    3. Plan the trial and the measure.
    4. Plan the hand-off to Maya.
      Done when: any site manager gets the same format and verified figures.
    Check your work
    Show model answer

    1. Frictions. Pasted extracts (connector), different prompts and formats (shared Project and a report Skill), figures computed in prose (code execution), different checks by person (a verification rule in instructions).

    2. Workflow. A shared "Weekly Ops Report" Project: instructions set the metric definitions and a rule to flag missing data; knowledge holds the metric glossary; the Drive connector reads that week's sheet; code execution computes on-time rate, pick errors and overtime; a Skill produces the one-page report in the VP's format.

    3. Trial and measure. For three weeks, two sites run both the old and new process; compare figures against the sheets and against each other. Measure VP reconciliation time (90 minutes at baseline), manager time per report and the number of figure corrections.

    4. Hand-off. Maya becomes the Project and Skill owner and approves changes. A one-page run guide lists inputs, steps, checks and escalation. Maya runs the full cycle once with the current builder reviewing.
