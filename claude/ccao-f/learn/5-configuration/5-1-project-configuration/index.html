    Configuring a Project

    Exam skillProject Configuration

    Applying Project configuration to a defined recurring use case, including instructions, knowledge sources, Skills, and scoped memory, and choosing among instruction, knowledge source, and Skill for each requirement while keeping unrelated work streams isolated.

    Configure a Project by putting each requirement in the right slot. Behavior rules go in instructions, reference facts in knowledge, multi-step procedures in Skills, and accumulated context in project-scoped memory, with unrelated or competing work kept in separate Projects.

    Written and maintained by Prakash Sridharan, Claude Certified Architect

    On this pageWhat you need to knowIn the examCheck your understandingApply itSources

    What you need to know

    Using Claude means writing a good prompt today. Operating Claude means configuring an environment so every conversation starts from the right baseline. A Project is that environment for one recurring use case.

    Four slots, four jobs

    SlotHoldsExample
    InstructionsBehavior for every chat: tone, format defaults, verification habits, escalation rules"Cite the source document for every factual claim; flag what the documents do not cover"
    KnowledgeReference facts and documentsThe current rate card, policy manual, brand guide
    SkillsRepeatable multi-step procedures and templates; set up at account level and usable in any ProjectFormatting proposals in the house template
    Project-scoped memoryWhat the Project has settled over timeRecurring concerns a business unit raised in earlier chats
    Decision rule
    Rule, reference or procedure?

    Ask what kind of thing each requirement is. A rule goes in instructions; a reference goes in knowledge; a procedure goes in a Skill. A behavior rule plus the facts it acts on usually needs two slots wired together: the citation rule in instructions, the documents it cites in knowledge.

    The most common mistakes

    • A 30-page manual pasted into instructions (bloats every chat; belongs in knowledge).
    • A 12-step procedure written as one instruction paragraph (steps get skipped; belongs in a Skill).
    • Firm rules left to memory (best effort and per user).
    • Every past version of a policy in knowledge (invites citing a superseded rule).

    Isolation and access

    Unrelated or competing work streams belong in separate Projects. Project-scoped memory keeps one client's context out of another client's chats. Instructions such as "keep the clients apart" are not isolation. On Team and Enterprise plans, share a Project only with the people who need it, especially for sensitive work such as performance reviews.

    Exam trap
    Duplicating a shared Skill

    A procedure used by every client Project should be one Skill reused everywhere, not hand-edited copies that drift apart.

    In the exam

    Items list requirements for a recurring use case and ask where each belongs, or how to fix a muddled Project. Sort each requirement into rule, reference, procedure or continuity, and isolate unrelated work. Distractors put procedures in knowledge, rules in memory, documents in instructions, or competing clients in one Project.

    Check your understanding

    Question 1

    Where should a team's current rate card go in a proposals Project?

    Show answer

    Answer: A. Reference facts belong in knowledge, where they can be replaced when they change.

    Question 2

    A 12-step report procedure written as one instruction paragraph keeps getting steps skipped. Best change?

    Show answer

    Answer: C. Multi-step procedures belong in Skills.

    Question 3

    A consultant serves two competing clients and wants continuity without mixing. Configuration?

    Show answer

    Answer: D. Separate Projects isolate instructions, knowledge and memory.

    Apply it: Configure Copperline's HR Project

    Exercise · about 20 minCase: Copperline Credit Union

    HR wants a Project to answer staff policy questions. Requirements: (1) answers based on the current policy manual and benefits summary; (2) every answer cites the policy section; (3) questions about medical leave, accommodations or disputes are referred to the HR manager; (4) answers in a fixed format: short answer, policy reference, next step; (5) a standard procedure for turning a question into an FAQ entry, used monthly; (6) only HR staff can edit the Project.

    1. Place each requirement in a slot.
    2. List what must not go in the Project.
    3. Say what memory should and should not hold.
      Done when: every requirement has exactly the right home.
    Check your work
    Show model answer

    1. Placement.

    • (1) Knowledge: the current manual and benefits summary only, older versions removed.
    • (2), (3) and (4) Instructions: citation rule, referral rule with the topics named, answer format.
    • (5) A Skill for the FAQ-entry procedure, owned by HR.
    • (6) Project sharing: HR staff can edit; other staff use it as permitted by the organization.

    2. Not in the Project. Superseded policy versions, individual employees' cases or medical details, and member data of any kind.

    3. Memory may hold recurring, non-sensitive context (common question themes). It must not hold anything about individual employees; the HR manager reviews it monthly.
