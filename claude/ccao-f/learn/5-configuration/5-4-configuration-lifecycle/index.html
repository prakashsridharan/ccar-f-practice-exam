    When a Configuration Drifts

    Exam skillConfiguration Lifecycle and Degradation

    Evaluating an established Claude configuration whose output quality has shifted, including instructions, knowledge freshness, Skill versions, and accumulated memory, to attribute the degradation to the responsible layer and restore performance.

    When a configuration that used to work starts producing worse output, trace the symptom to its layer (instructions, knowledge freshness, Skill version or accumulated memory), fix that layer, confirm recovery, and prevent recurrence with a regular review.

    Written and maintained by Prakash Sridharan, Claude Certified Architect

    On this pageWhat you need to knowIn the examCheck your understandingApply itSources

    What you need to know

    Configurations age. A standing instruction written for last year's process, a knowledge base holding superseded documents, a Skill that is out of date, or memory full of old facts will degrade output quietly, with no error message. The skill is to find the responsible layer, not to start rewriting prompts.

    Symptoms point to layers

    SymptomLikely layerFix
    Cites an old price, policy or templateKnowledge: a stale or duplicate documentReplace it; remove old versions
    Uses another client's terms, a departed person, an old preferenceMemory: accumulated, cross-workstream or outdated entriesEdit or delete entries; keep work streams in separate Projects
    The same format error in every run; changed right after a Skill updateSkill versionCheck, correct and re-upload the Skill, or ask its owner
    Follows an old scope or a dated detail exactlyInstructions: no longer match the current processUpdate the instruction; keep changing facts in knowledge
    Decision rule
    Use the timing

    Output that changed right after an upload points to knowledge; right after a Skill update, to the Skill. If instructions and Skills are unchanged, they cannot explain a change in output.

    Skill versions

    Anthropic-provided and organization-provisioned Skills can be updated centrally. A custom Skill you uploaded changes only when you upload a new version. Updating a template file on a shared drive does not change the Skill.

    Fix one layer at a time

    Changing instructions, knowledge and the model all at once may improve output, but nobody learns why, and the problem can return. Check layers in turn, fix the responsible one, then re-test a few outputs against the standard.

    Prevent drift

    • A monthly review for active Projects: do instructions match the current process, is knowledge current and de-duplicated, are the right Skills and versions in place, is memory accurate?
    • Review instructions whenever periods, roles or scope change.
    • Reset memory (after backing up what matters) when stale entries are too many to fix one by one.
    Exam trap
    The model as the fix

    Switching to a more capable model or raising effort affects reasoning, not whether the Project is grounded in current, correctly scoped knowledge.

    In the exam

    Items describe a Project that used to work and now shows specific symptoms, often with clues about what changed. Attribute each symptom to its layer and pick the fix for that layer, or the first thing to check. Distractors rewrite instructions that did not change, switch models, abandon the Project or change everything at once.

    Check your understanding

    Question 1

    A FAQ Project quotes a returns window the company changed two months ago. Instructions and Skills are unchanged. Most likely layer?

    Show answer

    Answer: A. Old facts with unchanged instructions and Skills point to knowledge.

    Question 2

    A team updated its offer-letter template on the shared drive, but letters from its custom Skill still lack the new clause. Why?

    Show answer

    Answer: D. Custom uploaded Skills are fixed until replaced.

    Question 3

    An owner fixed drift by changing instructions, knowledge and model at once. What was the problem?

    Show answer

    Answer: B. Diagnose one layer at a time to learn the cause.

    Apply it: Restore Copperline's HR Project

    Exercise · about 15 minCase: Copperline Credit Union

    The HR Project set up 14 months ago now quotes last year's 401(k) match, names a benefits manager who left, and, since IT updated the organization's document-formatting Skill last week, returns answers as paragraphs instead of the agreed table.

    1. Attribute each symptom to a layer.
    2. Fix each layer and say how you will confirm recovery.
    3. Set up prevention.
      Done when: each fix targets one layer and recovery is tested.
    Check your work
    Show model answer

    1. 401(k) figure: knowledge (last year's benefits summary). Departed manager: memory (and possibly an old contact list in knowledge). Paragraphs instead of tables: the updated Skill.

    2. Replace the benefits summary with the current one and remove the old version; delete memory entries about the departed manager and check knowledge for old contact lists; ask IT to check the updated Skill, then restore the table format or adjust the instruction to match the new version. Re-run ten common questions and compare with the expected answers.

    3. Linda Chu reviews instructions, knowledge, Skill versions and memory on the first Monday of each month, and immediately after any plan-year change or Skill update.
