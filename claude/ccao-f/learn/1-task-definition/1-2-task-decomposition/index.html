    Breaking Big Deliverables into Steps

    Exam skillTask Decomposition and Sequencing

    Applying task decomposition to deliverables too large or multifaceted for a single request, including staged prompts, follow-ups, Project workflows, prompting-strategy differences by task type, and validation checkpoints between steps.

    Deliverables with several distinct parts are several tasks. Run them as ordered steps, check each intermediate result before the next step builds on it, and match the prompting strategy to each step's task type.

    Written and maintained by Prakash Sridharan, Claude Certified Architect

    On this pageWhat you need to knowIn the examCheck your understandingApply itSources

    What you need to know

    A request such as "evaluate these four bids and choose a winner" hides four tasks: agree criteria, score each bid, weigh trade-offs, recommend. Asked in one prompt, Claude does each shallowly and the reasoning is invisible. Decomposition turns it into ordered steps, each producing a result you can check.

    Order the steps from foundation to synthesis

    1. Requirements or criteria first, so every later step has a target.
    2. Extraction and computation next. Numbers come from code execution, not prose.
    3. Analysis or comparison on the checked inputs.
    4. Synthesis last: the recommendation, summary or message built from finished parts.
    Decision rule
    Put a checkpoint where an error would spread

    Check the step that every later step depends on: the extracted list, the computed figures, the criteria. A wrong number caught there costs a minute; caught in the board pack it costs a meeting.

    Shared foundations for several deliverables

    When one source feeds several outputs (an all-staff email, a manager pack and an FAQ from one strategy), extract and confirm the shared content once, then draft each output from that confirmed list. Drafting each from the raw source invites three slightly different stories.

    Strategy differs by task type

    Task typeTightenLoosen
    AnalysisCriteria, standards, scopePhrasing
    ResearchQuestion, sources, citationsHow findings are synthesized
    DraftingAudience, tone, formatWord choice
    BrainstormingGoal and a few guardrailsVolume and range

    A staged campaign workflow uses loose prompts to generate concepts, then tight criteria to score them, then a detailed brief for the winner. Mixing the two in one prompt kills the range of ideas.

    One conversation or several

    Keep dependent steps in one conversation so each step sees the previous one. Run independent steps in separate conversations. When a conversation grows long, carry forward a checked summary rather than the whole thread. Work that spans days and reuses the same sources belongs in a Project.

    Exam trap
    Conclusion first

    Asking for the recommendation first and the evidence afterwards produces reasoning that justifies the answer instead of testing it.

    In the exam

    Items describe a single prompt that produced shallow or untraceable work, or a multi-step workflow where an error slipped through. Choose the sequence that builds a checked foundation first and the checkpoint that sits right after the step everything else depends on. Distractors ask for a longer single response, reverse the order, or check only at the end.

    Question 2

    Show answer

    Answer: B. Checking the foundation stops an error before it spreads.

    Question 3

    Show answer

    Apply it: Decompose Ironwood's carrier review

    Exercise · about 20 minCase: Ironwood Logistics

    Procurement must recommend which of five carriers to keep for next year. Inputs: last year's shipment records (a spreadsheet), each carrier's contract and scorecard, and a budget limit. Last quarter a miscalculated on-time rate nearly dropped a good carrier.

    1. Break the work into ordered steps.
    2. Mark each step as Claude, Claude with code execution, or a person.
    3. Place the checkpoints and say what each checks.
      Done when: a wrong on-time rate could not reach the recommendation.
    Check your work
    Show model answer

    1 and 2. Steps.

    1. Agree evaluation criteria and weights (on-time rate, damage claims, cost, contract terms) with the procurement manager. Person, drafted with Claude.
    2. Compute on-time rate and damage-claim rate per carrier from the shipment records. Claude with code execution.
    3. Extract key contract terms (price per mile, penalties, notice periods) into one table. Claude.
    4. Score each carrier against the weighted criteria. Claude, from the checked inputs.
    5. Draft the recommendation with trade-offs. Claude.
    6. Decide and approve. Procurement manager.

    3. Checkpoints. After step 1: criteria and weights approved. After step 2: spot-check two carriers' rates against the raw records and confirm the calculation logic. After step 3: compare the table with each contract's notice and penalty clauses. Before step 6: the manager reviews the scoring table, not just the conclusion.
