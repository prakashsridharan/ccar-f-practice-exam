    Matching Retrieval to Data and Queries

    Exam taskApply retrieval strategies matched to data shape and query pattern

    Match the retrieval method to the shape of the data and the way questions are asked, from vector search and keyword search to structured queries, metadata filters, reranking and agentic search.

    On this pageWhat you need to knowIn the examCheck your understandingApply itSources

    What you need to know

    "Add RAG" is not a design. The data an assistant needs comes in different shapes, and questions come in different patterns. Each combination has a retrieval method that fits it and several that do not.

    Match the method to the data shape

    Data shapeExamplesRetrieval method
    Unstructured textManuals, policies, articles, notesChunked index: dense, sparse or hybrid (lesson 3.5)
    Structured recordsOrders, claims, accounts, transactionsA query or API call with filters; never embeddings over rows
    Tables and metricsSales figures, KPIsSQL against the warehouse (the model can draft the query; code runs it with read-only, scoped access)
    Live stateStock, status, balancesA tool call to the owning system at question time
    Codebases and file treesRepositories, shared drivesAgentic search: the model lists, greps and opens files step by step

    Many assistants need several of these, behind one router or exposed as several tools.

    Match the method to the query pattern

    Query patternWhat helps
    Paraphrased, conceptual ("why does my table wobble?")Dense embeddings
    Exact identifiers (codes, clause numbers, names)Keyword or hybrid search
    Scoped ("in the 2025 policy wording", "for this product")Metadata filters applied before ranking
    Multi-part or multi-hop ("compare the excess in the old and new wordings")Query decomposition or an agent that retrieves in several steps
    High stakes, needs evidenceCitations to the retrieved passages, and quote-first answers

    Improving precision

    • Metadata filters (product, version, region, date, document type) remove whole classes of wrong answers before ranking.
    • Contextual retrieval adds a short description of each chunk's place in its document before indexing, which reduces misses from context-poor chunks; combined with hybrid search it lowers retrieval failures substantially.
    • Reranking takes the top few dozen candidates and reorders them with a stronger relevance model, keeping only the best handful. It improves quality and adds latency and cost per query, so it belongs where accuracy matters more than milliseconds.
    • Query rewriting turns a conversational question into a better search query, using the conversation so far.
    Decision rule
    Filter first, rank second

    When the question names a scope (a product, a policy version, a jurisdiction), apply it as a hard filter. Hoping similarity search ranks the right version first is how assistants quote last year's terms.

    Agentic search versus a one-shot index

    For codebases, file systems and very large or fast-changing collections, letting an agent search iteratively (list, search, open, follow references) can beat a precomputed index: it always sees the current files and can follow a trail. It is slower and costlier per question, so it suits investigation, not high-volume FAQ answering.

    Example
    One assistant, four retrieval methods

    An adjuster asks: "Is water damage from a burst pipe covered under this customer's policy, and have we paid a similar claim for them before?" The assistant calls Policy Admin for the customer's policy and its wording version (structured lookup), retrieves the relevant clauses from that wording version only (filtered hybrid search with citations), and queries prior claims for this customer (structured query). The answer quotes the clause and lists the prior claims; the coverage decision stays with the adjuster.

    Exam trap
    Embedding structured records

    Turning database rows into text and searching them by similarity gives fuzzy, stale answers to precise questions. Structured data is queried, not embedded.

    Exam trap
    Reranking everything

    Reranking adds a model call to every query. For a high-volume, latency-sensitive route where retrieval quality is already adequate, it can be the wrong trade.

    In the exam

    These questions describe the data and how users ask, then offer several retrieval designs. Pick the method for each data shape, add filters when the question names a scope, use hybrid search when identifiers matter, add reranking where accuracy outweighs latency, and choose agentic search for codebases or investigative tasks. Distractors apply one method to everything, usually vector search.

    Check your understanding

    Question 1

    Analysts ask "what was our revenue by region last quarter?" against a sales data warehouse. Which retrieval approach fits?

    Show answer

    Answer: B. Aggregations over structured data are what queries are for. Similarity search over rows cannot compute a correct total.

    Question 2

    An assistant keeps quoting terms from an outdated policy wording, although the question names the 2026 wording. What is the best fix?

    Show answer

    Answer: A. A scope named in the question should be a hard filter. Ranking and prompt instructions make the right version more likely; a filter makes the wrong one impossible.

    Question 3 · select 2

    Which TWO situations suit agentic, step-by-step search over a precomputed index?

    Show answer

    Answer: A, B. Agentic search shines when the path must be followed and the content changes. High-volume FAQs need a fast index, and a single order lookup is a direct tool call.

    Apply it: Plan retrieval for Prairie State's adjusters

    Exercise · about 15 minCase: Prairie State Mutual

    Prairie State wants an adjuster assistant that answers questions while a claim is being assessed. The sources are: policy wordings (structured PDFs with numbered clauses, three versions in force), the customer's policy record in Policy Admin, the customer's previous claims in ClaimsCore, and an internal guidance library of about 600 short articles on assessing different kinds of damage.

    1. Choose the retrieval method for each source, with the reason.
    2. Name the filters that must apply before ranking.
      Why: quoting the wrong wording version would be a costly error.
    3. Decide whether to rerank, given that adjusters are not in a real-time chat.
    4. Say what every answer must include so an adjuster can trust it.
    Check your work
    Show model answer

    1. Methods

    SourceMethodReason
    Policy wordingsHybrid search over section-based chunks, with clause numbers keptAdjusters ask both in plain words and by clause number
    Customer's policy recordPolicy Admin API callLive, authoritative state
    Previous claimsStructured query in ClaimsCore for this customerRecords, not documents
    Guidance libraryDense or hybrid search over one chunk per articleShort, self-contained articles asked about in plain words

    2. Filters. The wording version recorded on the customer's policy (from Policy Admin), and the product line (home or auto). Guidance articles filtered by damage type when the claim type is known.

    3. Reranking. Yes for policy wordings: adjusters can wait a second or two, and the cost of quoting the wrong clause is high. Not needed for the guidance library if recall is already good in evaluation.

    4. Every answer includes the quoted clause with its number and wording version, links to any prior claims it relied on, and a reminder that the coverage decision is the adjuster's.
