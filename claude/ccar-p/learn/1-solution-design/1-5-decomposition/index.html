Decomposing Complex Problems

Exam taskApply decomposition techniques for complex problem solving

Break a complex process into pieces owned by Claude, by existing systems and by people, then split Claude's share along the lines that make it testable.

On this pageWhat you need to knowIn the examCheck your understandingApply itSources

What you need to know

Decomposition is the step between "here is the business process" and "here is the architecture". Done well, it makes every later decision easier: each piece can be given to the right owner, tested on its own and replaced without disturbing the rest.

First cut: who owns each piece

Every solution has three possible owners.

OwnerWhat it should ownExamples
ClaudeLanguage work: reading, extracting, classifying, summarizing, planning, draftingRead a free-text complaint and identify the product and issue
Existing systemsDeterministic logic and authoritative data the business already trustsAccount balances, eligibility rules, pricing, the record of truth
PeopleJudgment, exceptions, approvals, decisions where being right matters more than being fastApproving a large refund, deciding an unusual claim

The most frequent mistake is to give everything to Claude because it can attempt everything. Over-assigning makes the system more expensive, slower, harder to audit and less accurate on precisely the tasks existing systems already do well.

Example
Warranty claim handling
  • Read the customer's description and photos and identify the fault: Claude.
  • Check whether the product is still under warranty: the warranty system.
  • Calculate the refund or replacement value: the pricing service, not the model.
  • Draft the customer response: Claude.
  • Approve claims above a value threshold or outside policy: a person.

Second cut: how to split Claude's share

Once you know what Claude owns, split that work along natural seams. Each seam maps to a workflow shape from lesson 1.3.

  • By stage: when one result feeds the next (extract, then classify, then summarize). This becomes a chain, and you can test each stage separately.
  • By input type: when different kinds of request need different handling. This becomes a router.
  • By independent unit: when the same task applies to many separate items, such as one per document or one per region. This becomes parallel work or subagents.
  • By draft and check: when quality can be verified but one attempt is not reliable enough. This becomes an evaluator-optimizer loop.

Check each piece against the model's limits

For every piece Claude owns, ask the four feasibility questions from lesson 1.1:

  • Does it need precise values? Then the value comes from a system or from code, and Claude only works with it.
  • Does it need current or specialized knowledge? Then bring that knowledge in through retrieval or a tool.
  • Does the input fit in the context window? If not, split it further or load it progressively.
  • Is the instruction concrete and checkable? If not, sharpen it, or move the logic into code.
Decision rule
Numbers belong to code

Totals, interest, tax, dosage, dates between events: anything that must be exactly right is computed deterministically, by an existing system or by code execution. Claude can explain the result; it should not be the calculator.

Put people where the stakes are

Human steps are part of the decomposition, not a patch added at the end. Place approval at the point where a decision becomes consequential or irreversible, such as issuing money, changing a record of truth, or sending something on the company's behalf. Routine, low-risk outputs can flow without review, which keeps reviewers focused on what matters.

Exam trap
"Let Claude check the rules"

When a scenario includes a published policy, a rules table or an eligibility service, options that ask Claude to apply those rules from memory or from the prompt are usually distractors. The existing system applies the rule; Claude handles the language around it.

Exam trap
Decomposing too finely

Splitting work into many tiny model calls adds latency, cost and handoff errors. Split where there is a real seam: a different owner, a different input type, an independent unit, or a step you need to test on its own.

In the exam

Decomposition questions usually describe a business process and ask which division of responsibilities is best. The right option gives language tasks to Claude, authoritative data and rules to existing systems, and consequential approvals to people, often with low-confidence cases routed to review. Watch for options that send authoritative checks to the model, remove a required human approval for speed, or make a person retype work that Claude could safely prepare.

Check your understanding

Question 1

In a claims process, which task should stay with the existing policy administration system?

Show answer

Answer: D. Whether a policy was in force is an authoritative fact held by the system of record. The other three are language tasks that suit Claude.

Question 2

A lending assistant must quote the monthly repayment for a given rate and term. How should the figure be produced?

Show answer

Answer: C. Exact figures belong to deterministic code or the system that owns the calculation. Claude adds value by explaining the result, not by being the calculator.

Question 3

Which way of splitting Claude's work naturally becomes a routing workflow?

Show answer

Answer: B. Different kinds of input needing different handling is the cue for routing. The others map to parallel work, an evaluator-optimizer loop and a chain.

Apply it: Decide who owns each step

Exercise · about 15 minCase: Lakeview Regional Medical Center

Lakeview wants Claude to help with discharge summaries. Take the seven steps of today's process from the case and decide who should own each one: Claude, an existing system, or a person.

  1. Assign an owner to each of the seven steps, with a one-line reason.
    Why: over-assigning to the model is the most common decomposition mistake.
  2. List the values that must come from a system of record, never from the model.
    Done when: every value a wrong guess could harm a patient with is on the list.
  3. Place the human checkpoint and say what the physician sees when they review.
