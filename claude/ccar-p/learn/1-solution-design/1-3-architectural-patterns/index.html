    Selecting an Architectural Pattern

    Exam taskSelect appropriate architectural patterns (workflow, agentic, augmented LLM)

    Choose between an augmented LLM call, a workflow and an agent by asking which constraint is tightest, and default to the simplest pattern that meets it.

    On this pageWhat you need to knowIn the examCheck your understandingApply itSources

    What you need to know

    There are three ways to structure Claude's part in a system. The difference between them is who controls the sequence of steps: your code or the model.

    Augmented LLM

    One bounded call. You send a request, possibly with retrieval results, tools or extended thinking enabled, and Claude completes one job. Your application decides what happens next; nothing branches on the model's choices. Use it when the task is well defined and the result can be checked.

    Example: summarize a customer complaint and draft a reply for an agent to review.

    Workflow

    The task is split into named steps that your code runs in a fixed order. Some steps call Claude, others call existing systems or apply rules. Because the control flow lives in code, each step can be logged, tested, monitored and audited like any other software. Use it when the steps are known in advance and mistakes are expensive.

    Workflows come in four common shapes:

    ShapeHow it worksExample
    ChainingEach step consumes the previous step's outputExtract obligations from a contract, then rate their risk, then write a summary
    RoutingA classifier picks the path for each inputBilling questions to account data, technical ones to product docs, complaints to a person
    ParallelizationIndependent pieces run at the same time and are combinedTwelve supplier contracts reviewed concurrently, results merged into one report
    Evaluator-optimizerOne call drafts, another checks against criteria, and the draft is revised until it passes or a retry limit is hitA customer reply checked against a tone and completeness rubric

    These shapes combine freely. A routed workflow can have a chained branch and an evaluator loop inside it.

    Agent

    Claude receives a goal and a set of tools and decides for itself which tools to call and in what order. The path is not written down anywhere you can inspect in advance. Use it only when the steps genuinely cannot be listed beforehand, such as investigating an unfamiliar codebase or researching across many sources, and when an unexpected result can be caught and recovered.

    A production agent always comes with limits: a minimal tool set, per-turn and total budgets, explicit permissions, a stopping condition, and human approval before consequential actions. These are part of the pattern, not optional extras.

    How to choose

    Walk through five factors. The first one that rules a pattern out usually decides.

    FactorQuestionAugmented LLMWorkflowAgent
    PredictabilityCan the steps be listed in advance?One bounded taskYes, you wrote themNo, by design
    Error costWhat does a wrong answer cost?No guards between stepsChecks between every stepErrors can compound over many turns
    ObservabilityCan operations reconstruct what happened?One call, easy to logLogs like ordinary codeA long transcript that most tooling cannot alert on
    LatencyWhat is the user-visible deadline?FastestPredictable, adds up per stepOpen-ended; plan for the worst case
    CostWhat is the cost per request at volume?LowestGrows with stepsHighest and least predictable
    Decision rule
    Start simple, escalate on evidence

    Choose the simplest pattern that meets the requirements, then measure it in production. Move to a more autonomous pattern only when data shows the simpler one falling short.

    Example
    Supplier onboarding checks

    A manufacturer screens every new supplier through the same nine checks (sanctions list, tax registration, insurance certificate, and so on), and compliance must be able to show which check passed or failed for each supplier. The steps are known, errors are costly and every step must be reconstructable, so a workflow wins: code runs the checks in order, Claude reads the submitted certificates where interpretation is needed, and rule-based validation sits between steps. An agent choosing its own order would undermine the audit trail however capable it is.

    Exam trap
    "The agent can handle anything"

    An agent is the most flexible pattern and also the least predictable, hardest to observe and most expensive. When a scenario lists fixed steps, audit needs or tight latency, the agent option is almost always the distractor.

    Exam trap
    Confusing tools with autonomy

    An augmented LLM call can use tools and retrieval and still not be an agent. What makes an agent is that the model decides the sequence across multiple steps, not that a tool is present.

    In the exam

    Read the scenario for the deciding constraint. Phrases like "the steps never change", "every decision must be auditable" or "a three-second response" point to a workflow or a single call. Phrases like "the investigation path differs every time" or "unfamiliar codebase" point to an agent, and then the best option is the one that also bounds it with budgets, permissions and approval gates. When two options use the same pattern, prefer the one that adds the controls the scenario's risks call for.

    Check your understanding

    Question 1

    A legal team wants each contract processed the same way: extract the clauses, rate each clause's risk, then write a summary. Each stage's output must be validated before the next stage uses it. Which pattern fits?

    Show answer

    Answer: A. The steps are fixed and each one feeds the next, with a check in between. That is a chained workflow. A single call removes the checkpoints, and an agent or multi-agent design adds cost and unpredictability for no gain.

    Question 2

    What makes a design an agent rather than an augmented LLM call?

    Show answer

    Answer: D. Tools and retrieval can be added to a single bounded call. A design becomes an agent when the model controls the sequence of steps toward a goal.

    Question 3 · select 2

    An engineering team needs incidents investigated across logs, dashboards and code, and the path differs every time. Which TWO controls should come with the agent?

    Show answer

    Answer: A, D. An open-ended investigation suits an agent, but only a bounded one: budgets and a stopping rule cap cost and runaway loops, and approval gates keep consequential actions with people.

    Apply it: Choose the pattern for support

    Exercise · about 15 minCase: Hollis & Grant Home

    Hollis & Grant Home wants Claude in its chat and email support. One engineer proposes "a single agent with access to every system". Use the five factors to choose the pattern, then decide how each contact type is handled.

    1. Score the five factors (predictability, error cost, observability, latency, cost) for Hollis & Grant's support, using the case facts.
      Done when: each factor has one line that quotes a fact from the case.
    2. Name the deciding factor and the overall pattern it points to.
      Why: the exam rewards the simplest pattern that meets the tightest constraint.
    3. Decide the handling for each contact type in the table from the case.
      Done when: every contact type has a path, and no state-changing action happens without the right check.
    4. Say what evidence would justify an agent later, if any.
    Check your work
    Show model answer

    1. Five factors

    FactorHollis & Grant
    PredictabilityFive known contact types cover all volume; the steps for each are known
    Error costWrong order status or a wrong refund is costly; refunds over $250 need a supervisor
    ObservabilitySupport leads must be able to see why a contact was answered as it was
    LatencyChat needs a first response within 3 seconds at the 95th percentile
    Cost$18,000 a month must cover peak season at 2.5 times normal volume

    2. Deciding factor and pattern. Latency and predictability together rule out an open-ended agent: a multi-turn tool loop cannot reliably answer within 3 seconds, and the paths are known in advance. The pattern is a routing workflow: a fast classifier, then a fixed path per contact type.

    3. Handling per contact type

    Contact typePath
    Order statusAugmented call: tool call to the Order Management System, then Claude phrases the answer
    Returns and refundsWorkflow: Claude collects the details, the returns portal applies the rules, refunds over $250 go to a supervisor
    Product questionsRetrieval over manuals and help centre, answer with a citation
    Account and billingRetrieval for policy questions; anything touching payment goes to an agent, and card data never enters the context
    ComplaintsHand off to a person with a summary of the conversation

    4. Evidence for an agent. Only if production data shows a meaningful share of contacts that the router cannot place and that need several look-ups in an unpredictable order, and only for email, where the 4-hour target leaves room for it.
