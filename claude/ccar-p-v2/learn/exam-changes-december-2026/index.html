    What changed in the CCAR-P exam on 7 December 2026

    Anthropic's CCAR-P exam guide 1.1 applies from 7 December 2026. It has more items, new domain weights, 39 skills in place of 38 tasks, and new topics such as deployment surfaces, prompt injection and model migration. Here is every change, and what to study if you prepared for guide 1.0.

    Written and maintained by Prakash Sridharan, Claude Certified Architect

    On this pageAt a glanceDomain weightsFrom tasks to skillsNew and expanded topics, domain by domainPolicy changesIf you studied for guide 1.0

    Anthropic has published version 1.1 of the Claude Certified Architect - Professional (CCAR-P) exam guide, effective 7 December 2026. Exams taken from that date follow guide 1.1; exams taken before it follow guide 1.0 (July 2026). This page compares the two guides section by section. Everything here comes from the two published guides, not from the exam itself.

    At a glance

    Guide 1.0 (until 6 December)Guide 1.1 (from 7 December)
    Items6370: 60 scored and 10 unscored, not identified
    Time120 minutes120 minutes
    Time per itemabout 1 minute 54 secondsabout 1 minute 43 seconds
    Item formatMultiple choice and multiple response; each item states how many to selectScenario-based multiple choice; each item states how many to select
    Objectives38 tasks39 skills, each with a description
    Foundations examNot mentionedRecommended, not required; its scope is assumed knowledge
    Passing score720 on a scale of 100 to 1,000Unchanged
    Fee and validity$175, valid 12 monthsUnchanged

    The two biggest practical changes: seven more items in the same 120 minutes, and objectives written as analysis skills rather than short tasks.

    Domain weights

    DomainGuide 1.0Guide 1.1ChangeAbout this many scored items in 1.1

    Domain 6 is cut in half. Its weight moves mostly to Integration and to Governance, Safety and Risk Management, which together are now more than a third of the exam. The item counts are the weights applied to the 60 scored items, rounded; the guide gives only percentages.

    From tasks to skills

    Guide 1.0 listed short tasks, such as "Select appropriate Claude models based on trade-offs". Guide 1.1 replaces them with 39 named skills, and each one describes the judgment being tested: given a scenario with stated constraints, evaluate a design, find what fails first, and select the option that meets every constraint. Most descriptions start with Analyzing, Evaluating, Selecting or Identifying.

    Three things follow from that:

    • Expect evidence in the stem. Guide 1.1 tells candidates to practice reviewing architecture diagrams, configuration files, logs and traces, evaluation results and code, because exam scenarios present such artifacts.
    • Look for the binding constraint. Many skills ask for the option that satisfies all stated constraints, or that relieves the binding one at least cost to the others. The sample questions in guide 1.1 reward naming that constraint and accepting its trade-off.
    • Longer items, less time. The 1.1 sample questions are noticeably longer than the 1.0 ones, and there are seven more items in the same time.

    New and expanded topics, domain by domain

    Domain 1: Solution Design and Architecture

    • Deployment surfaces and agent runtimes are new: choosing between the Anthropic API, Amazon Bedrock, Google Vertex AI and Microsoft Foundry, and between a Messages API loop, a self-hosted Agent SDK or headless Claude Code, and Claude Managed Agents, under residency, compliance and ownership constraints. 1.6 Deployment Surfaces and Agent Runtimes
    • Task delegation between Claude and humans is now a skill of its own, judged by reversibility, stakes and accountability. 1.1 Delegating Work Between Claude and People
    • Pattern selection adds Skills-based patterns to workflow, agentic and augmented LLM. 1.3 Selecting an Architectural Pattern
    • Architecture evaluation asks which component fails first under a stated load or trust condition. 1.2 Evaluating an End-to-End Architecture

    Domain 2: Claude Models, Prompting and Context Engineering

    • Reasoning effort and context lifecycle is new: context editing, the memory tool and compaction for long-running agents. 2.6 Reasoning Effort and the Context Lifecycle
    • Prompting techniques now contrast prompted reasoning with native thinking, and include structured output. 2.3 Choosing a Prompting Technique
    • Caching becomes a skill about cache breakpoints: stable content before dynamic content. 2.5 Cache Breakpoints and Reusable Packaging

    Domain 3: Integration

    • Production reliability controls are new: rate-limit handling, retry and backoff, idempotency for side-effecting tools, and fallback routing. 3.8 Production Reliability Controls
    • Retrieval now covers choosing between a RAG pipeline, agentic search with tools and full-corpus context, plus contextual retrieval and fallback. 3.5 Selecting a Retrieval Architecture
    • Tool configuration is judged against least privilege and minimal footprint. 3.1 Least-Privilege Tool Configuration

    Domain 4: Evaluation, Testing and Optimization

    • LLM-as-judge design and bias is new: position, verbosity, self-preference and judge drift. 4.3 LLM-as-Judge Design and Bias
    • Model version migration is new: pin, re-tune prompts, re-baseline evaluations or defer, within a deprecation timeline. 4.7 Model Version Migration
    • A/B testing becomes experimental design, including how many trials per case separate a real effect from run-to-run variance. 4.4 Experimental Design for Comparing Configurations
    • Diagnosis is now root-cause isolation from logs and traces among prompt failure, retrieval failure, hallucination, tool or subagent error, and model mismatch. 4.5 Isolating Root Causes from Logs and Traces

    Domain 5: Governance, Safety and Risk Management

    • Prompt injection gets its own skill, covering retrieved documents, tool results, MCP server responses and third-party Skills. 5.2 Prompt Injection Surface and Controls
    • Risk assessment adds token and quota exhaustion and dependency and supply-chain risk, ranked by exposure. 5.3 Risk Assessment and Ranking
    • Compliance moves from naming regulations to selecting architectural controls: data residency and deployment surface, zero data retention, PII redaction, audit logging and tenant isolation. 5.5 Architectural Controls for Compliance
    • Bias is now about identifying its source: data, prompt framing or evaluation design. 5.6 Identifying and Mitigating Bias

    Domain 6: Stakeholder Communication and Lifecycle Management

    Five tasks become three skills: spotting unsupportable commitments in discovery notes or a draft SLA 6.1 Unsupportable Commitments in Requirements and SLAs, reviewing architecture decision records 6.2 Architecture Decision Records, and checking an operational handoff package for gaps 6.3 Operational Handoff Completeness. Structured discovery, feedback loops and lifecycle support are no longer separate objectives.

    Domain 7: Developer Productivity and Operational Enablement

    • Packaging and distributing Claude Code workflows is new: plugins, marketplaces and managed settings. 7.1 Packaging and Distributing Claude Code Workflows
    • Configuration names the permission modes (default, acceptEdits, plan, auto, dontAsk, bypassPermissions), hooks, subagents and headless or CI operation. 7.2 Configuring the Agent SDK and Claude Code
    • Accountability for AI-generated code is new: the control that keeps human ownership of code Claude writes. 7.3 Accountability for AI-Generated Code

    Policy changes

    • Rescheduling and canceling: online proctored exams can be changed up to one hour before the appointment and test center exams up to 48 hours before. Guide 1.0 allowed changes up to 24 hours before for both.
    • Name on your registration: you can correct it yourself once in your Partner Academy exam profile; guide 1.0 asked you to email support.
    • Retakes are unchanged: 14 days after a first failed attempt, 30 after the second, 90 after the third, and up to four attempts in 12 months.

    If you studied for guide 1.0

    1. Read the eight new lessons first: 1.6 Deployment Surfaces and Agent Runtimes, 2.6 Reasoning Effort and the Context Lifecycle, 3.8 Production Reliability Controls, 4.3 LLM-as-Judge Design and Bias, 4.7 Model Version Migration, 5.2 Prompt Injection Surface and Controls, 7.1 Packaging and Distributing Claude Code Workflows and 7.3 Accountability for AI-Generated Code.
    2. Rebalance your time. Spend less on discovery and stakeholder management and more on Integration and Governance, which gained the most weight.
    3. Practice from evidence. For each lesson, work out what a log, trace or configuration would look like if that skill were being tested, and what the binding constraint would be.
    4. Review the Foundations scope. Guide 1.1 assumes it. The CCAR-F learning guide covers it.
    5. Practice at the new pace. The Version 1.1 practice tests have 70 items in 120 minutes, the same pace as the exam.

    Sources: Anthropic's Claude Certified Architect - Professional exam guides, version 1.0 (July 2026) and version 1.1 (December 2026), published on the Anthropic Partner Academy.
