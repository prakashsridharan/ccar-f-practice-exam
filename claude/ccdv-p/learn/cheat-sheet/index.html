    How to read a CCDV-P question

    Most items describe a Claude system already in production and show evidence from it: traces, error mixes, token breakdowns, agreement rates, latency splits, red-team findings. Six habits pick the right answer:

    1. Read the evidence before the options. The numbers usually point to one stage or one constraint.
    2. Classify before you fix. Rate limit, refusal or length stop; recall, ranking or generation; model, harness, tool or data.
    3. Enforce outside the model. Limits, permissions, hooks, gates and sandboxes, not prompt instructions, when stakes are real.
    4. Mitigate first, diagnose second. A tested rollback or a narrow flag before the root cause is known.
    5. Measure the instrument. Judges against human labels, gates with repeated trials, metrics by segment.
    6. Change one thing, then measure. The narrowest fix at the layer that failed.

    On exam day

    • 70 items in 120 minutes is about 1 minute 40 seconds each. Ten items are unscored and not marked, so treat every item as scored. Read how many responses to select before the options.
    • Every "Not" above is a real trap. If an option sounds safe but does not touch the cause the evidence shows, it is probably wrong.
    • The score is scaled from 100 to 1,000 with 720 to pass, so a raw percentage does not convert directly. Aim for 80% or more in the practice tests.
