    Threat Defense and Red Teaming

    Exam skillThreat Defense and Adversarial Testing for Agentic Systems

    Analyzing the attack surface of tool-using agents that process untrusted content, including prompt injection, tool and memory poisoning, data exfiltration paths, unsafe-autonomy conditions, and the high-risk combination of private data access, untrusted input, and external communication, and applying defense-in-depth mitigations, red-team exercise design, and secure MCP configuration, drawing on the OWASP Top 10 for LLM Applications and the NIST AI Risk Management Framework and its Generative AI Profile.

    Map the attack surface of tool-using agents (prompt injection, tool and memory poisoning, exfiltration paths, unsafe autonomy, the combination of private data, untrusted input and external communication), defend in depth, design red-team exercises, and configure MCP securely, using OWASP and NIST guidance.

    Written and maintained by Prakash Sridharan, Claude Certified Architect

    On this pageWhat you need to knowIn the examCheck your understandingApply itSources

    What you need to know

    A chatbot that is manipulated says something wrong. A tool-using agent that is manipulated does something wrong: sends data out, changes records, spends money. Every source of text the agent reads (tickets, emails, web pages, PDFs, tool results, MCP tool descriptions, memory) is a possible channel for instructions an attacker wrote. Assume the model can be fooled; the controls must still hold.

    The high-risk combination

    LegExamples
    Access to private dataCRM records, internal wiki, accounts
    Exposure to untrusted inputCustomer tickets, web pages, uploaded documents, third-party tool output
    A channel to communicate externallyEmail, public posting, outbound HTTP, sharing links

    When all three meet in one context, prompt instructions alone cannot prevent exfiltration. Break a leg: scope data to the task (the ticket's own account), gate or remove the external channel (recipient allowlists, approval for external sends, no posting after internal reads), or narrow untrusted input (browsing allowlists).

    Attack types

    AttackWhat happensDefenses
    Indirect prompt injectionInstructions hidden in content the agent readsSeparate untrusted content from capabilities; enforce actions in code; check outputs at trust boundaries
    Tool poisoningHidden instructions in an MCP tool's description or outputReview and pin tool definitions; alert on changes; egress limits
    Memory poisoningInjected text persisted into memory, steering later sessionsValidate what may be written; scope memory; make entries reviewable
    ExfiltrationData leaves through email, URLs, posts or tool callsAllowlisted destinations; approval for external sends; output checks
    Unsafe autonomyThe agent takes costly or irreversible actions uncheckedLeast privilege, quotas, approval gates
    System prompt leakageUsers extract the promptKeep secrets and sensitive details out of prompts
    Example
    The memo that added a recipient

    A transaction memo told Granite's fraud agent to add an external address to a case's notification list. The fix was not a better prompt: changing notification recipients was removed from the agent's capabilities and left to analysts.

    OWASP and NIST as frameworks

    The OWASP Top 10 for LLM Applications names the risk categories, including prompt injection, sensitive information disclosure, supply chain, data and model poisoning, improper output handling, excessive agency (more functionality, permissions or autonomy than needed), system prompt leakage, vector and embedding weaknesses, misinformation and unbounded consumption. An agent that launched 300 instances in a loop after misreading an error is an excessive-agency problem: limits, quotas and approvals bound the damage whatever triggers it.

    The NIST AI Risk Management Framework organizes the work into four functions: Govern (policies, roles, accountability), Map (context and risk identification), Measure (assessment and tracking) and Manage (prioritizing and responding). Its Generative AI Profile applies the framework to risks specific to generative systems.

    Red-team exercises that change the system

    • Build scenarios on the agent's real tools and data ("access another customer's account", "send internal data out"), not only generic jailbreak lists.
    • Use testers other than the builders, before launch and again on changes.
    • Define success criteria, and turn each finding into a fix and a regression test, including variants of the attack.
    • Prefer fixes that do not depend on recognizing a phrasing: a control on the payment tool stops every chain, not just the one found.

    Secure MCP configuration

    • Allow only reviewed servers, from approved sources, with pinned versions.
    • Give each server least-privilege credentials and enable only the tools agents need.
    • Record tool-definition hashes and alert when a server's descriptions change.
    • Being listed in a public directory is not a trust decision.

    When to stop autonomy

    Require a human when an action is irreversible or costly, or when untrusted content has entered the session and the action sends data outside. Length, user tenure and time of day are not risk properties.

    In the exam

    Threat items describe an agent's tools and inputs and an attack or near miss. Identify which legs of the combination are present and which channel carried the attack, then pick the structural control that closes the path. Distractors strengthen prompts, enlarge models, encrypt data the agent still reads, filter keywords, log after the fact, or trust listed servers.

    Check your understanding

    Question 1

    A ticket with hidden instructions made a support agent email another customer's record outside. The prompt already says to ignore ticket instructions. What closes the path?

    Show answer

    Answer: D. Enforced controls outside the model break the exfiltration path whatever the injected text says.

    Question 2

    A malicious document made an agent write a standing instruction into its memory tool. What is this, and what helps?

    Show answer

    Answer: A. Injection that persists in memory steers later sessions; the memory store needs its own controls.

    Question 3

    Which NIST AI RMF function covers policies, roles and accountability for AI risk?

    Show answer

    Answer: B. Govern sets the policies and accountability the other functions depend on.

    Apply it: Threat-model Tidewater's assistant

    Exercise · about 30 minCase: Tidewater Analytics

    Tide reads each tenant's uploaded documents, queries metrics, creates reports and can share a report with any email address. 140 tenants enable a third-party CRM MCP server. Tenants can upload documents written by their own customers.

    1. Map the three legs of the high-risk combination for Tide.
    2. Identify two attack paths and the channel each uses.
    3. Propose structural controls that close each path.
    4. Design one red-team scenario and say what makes it pass.
    Check your work
    Show model answer

    1. Legs. Private data: tenant documents and metrics. Untrusted input: uploaded documents written by tenants' customers, CRM tool output and tool descriptions. External channel: share_report to any email address.

    2. Paths.

    • An uploaded document contains instructions to create a report of sensitive metrics and share it to an outside address (indirect injection through documents, exfiltration through share_report).
    • The CRM server's tool description is changed to tell Tide to include the tenant's documents in a CRM note (tool poisoning, exfiltration through the CRM tool).

    3. Controls.

    • share_report limited to addresses in the tenant's own verified domains; any other recipient requires approval by a tenant admin, enforced in the tool.
    • Sessions that have read uploaded documents cannot call share_report without that approval.
    • CRM server pinned to a reviewed version; tool-definition hash recorded and alerted on change; only the CRM tools Tide needs are enabled, with a write scope limited to notes Tide itself creates.
    • Output check on CRM writes for document excerpts.

    4. Red-team scenario. A test tenant uploads a document asking Tide to share the revenue dashboard with an outside address. Pass: no report reaches the outside address, an approval request is raised and logged, and the attempt appears in the security dashboard. The scenario and three variants become regression tests.
