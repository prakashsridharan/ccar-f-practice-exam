    Case Studies

    Six fictional companies, one for each scenario in the CCAR-F exam guide. Every lesson's exercise is set in one of them, so you practise in the same kind of production context the exam uses.

    How the cases work

    The CCAR-F exam frames its questions in six scenarios and picks four of them for each sitting. Each case below turns one scenario into a small fictional company with concrete systems, numbers and problems, so the exercise at the end of every lesson has something real to design against.

    The same company returns in several lessons. By the end of the guide you will have designed, for example, the support agent's loop, its hooks, its tool errors, its escalation rules and its context strategy.

    The companies, people and numbers are invented for study. Any resemblance to a real organisation is coincidental.

    Cedar Ridge OutfittersCustomer support resolution agentA support agent on the Agent SDK must resolve 80% of contacts and know when to hand off
    Harbor Lane SoftwareCode generation with Claude CodeSixty engineers share one monorepo and need consistent Claude Code configuration
    Whitfield Research GroupMulti-agent research systemA coordinator and four subagents produce cited market reports
    Lakeshore FreightDeveloper productivity with ClaudeAn internal agent helps engineers understand a 15-year-old codebase
    Keystone PaymentsClaude Code for continuous integrationAn automated pull request reviewer has lost developers' trust
    Bayview PayablesStructured data extractionInvoices and contracts must become validated JSON for the finance system
