    How to read a CCAR-F question

    Most items describe a working system with one flaw and ask for the best fix. Five habits find it:

    1. "Must always" or "must never" means code, not wording. Use a hook, a gate or a permission. A louder prompt still fails sometimes.
    2. Fix where it broke, not where it shows. A report skips a whole subtopic? The searches were fine; the coordinator never asked for it.
    3. Pick the targeted fix. A bigger model, a larger context window or temperature 0 is almost never the answer.
    4. Never hide a failure. An error is not an empty result, and a timeout is not "no data".
    5. Ask instead of guessing. Two customers match? Ask for an order number or an email.

    Distractors the exam keeps offering

    Every "Not" above is a real trap. The ones that come back most often: louder wording (CAPITALS, "CRITICAL"), temperature 0, a bigger model or context window, every tool for every agent, retrying every error, returning empty on failure, same-session self-review, an iteration cap as the stop signal, and escalating on sentiment. If an option sounds safe but does not touch the part that broke, it is probably wrong.

    On exam day

    • 60 items in 120 minutes is two minutes each: flag anything slow. Read how many responses to select before the options.
    • Find the constraint in the question ("must always", "under 3 seconds", "teammates cannot see"). It usually rules out two options.
    • The score is scaled to 1,000 with 720 to pass, so a raw percentage does not convert directly. Aim for 80% or more in the practice tests.
