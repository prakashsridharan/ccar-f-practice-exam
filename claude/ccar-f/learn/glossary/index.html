    Glossary

    Plain-English definitions of the 55 key terms in the CCAR-F learning guide, each linked to the lessons that teach it.

    Written and maintained by Prakash Sridharan, Claude Certified Architect

    ABCEFGHILMOPRSTV

    A

    Agent

    A system in which a model uses tools in a loop to reach a goal, choosing its own next steps instead of following a fixed path set in code.

    Also: agents, AI agent

    Lessons 1.5 Agent SDK Hooks: Interception and Normalization2.2 Structured Error Responses5.4 Context in Large Codebase Exploration

    Agentic loop

    The cycle an agent runs: Claude replies, the code runs any tools it asked for, the results go back, and this repeats until Claude ends its turn or a limit is reached.

    Also: agent loop

    Lesson 1.1 The Agentic Loop and stop_reason

    allowed-tools

    A list of tools in a skill, command or agent configuration, or on the command line. Depending on where it is set, it pre-approves those tools or limits Claude to them, so check the current documentation for each place.

    Lesson 3.2 Custom Slash Commands and Skills

    B

    Bias

    A systematic skew in output, such as favoring certain groups, viewpoints or answer positions. Found by testing varied inputs and reviewing the results.

    Also: biased

    Lesson 4.2 Few-Shot Prompting for Consistency

    C

    Chunking

    Splitting documents into smaller passages for indexing and retrieval. Chunk size and where the boundaries fall decide what retrieval can find.

    Also: chunk, chunks

    Lesson 4.5 Batch Processing Strategies

    Citations

    References from Claude's answer to the exact source passages behind it, so a reader can check each claim.

    Also: citation, cite sources

    Lessons 1.3 Spawning Subagents and Passing Context4.2 Few-Shot Prompting for Consistency5.6 Provenance and Uncertainty in Synthesis

    Claude Agent SDK

    Anthropic's library, for Python and TypeScript, for building agents on the same agent loop, tools and context management that power Claude Code.

    Also: Agent SDK

    Lessons 1.1 The Agentic Loop and stop_reason1.3 Spawning Subagents and Passing Context1.4 Workflow Enforcement and Human Handoff

    Claude Code

    Anthropic's agentic coding tool. It reads code, edits files and runs commands, in the terminal, an IDE, the desktop app or the browser.

    Lessons 1.5 Agent SDK Hooks: Interception and Normalization3.2 Custom Slash Commands and Skills3.6 Claude Code in CI/CD Pipelines

    CLAUDE.md

    A Markdown file that Claude Code loads at the start of a session, holding instructions such as build commands and coding conventions. It can be set for the user, the project or a single directory.

    Lessons 3.1 CLAUDE.md Hierarchy and Organization3.2 Custom Slash Commands and Skills3.3 Path-Specific Rules

    Compaction

    Summarizing the earlier part of a long conversation to free space in the context window while keeping the facts still needed.

    Also: compact, auto-compact

    Lessons 1.7 Sessions: Resume, Fork or Start Fresh5.4 Context in Large Codebase Exploration

    Confidence calibration

    How well a stated confidence matches real accuracy. Well-calibrated scores can be used to send low-confidence cases to a person.

    Also: calibration, calibrated, well-calibrated

    Lessons 4.6 Multi-Instance and Multi-Pass Review5.5 Human Review and Confidence Calibration

    Context window

    The maximum amount of text, counted in tokens, that a model can consider in one request: the system prompt, the conversation so far, tool definitions and results, and its own reply. Whatever does not fit is not seen.

    Also: context length

    Lessons 1.2 Coordinator-Subagent Orchestration5.1 Preserving Facts in Long Conversations

    E

    Escalation

    Routing a case from the automated system to a person, triggered by rules such as low confidence, high value, a policy exception or the customer asking for one.

    Also: escalate, escalated, escalates

    Lessons 1.4 Workflow Enforcement and Human Handoff2.2 Structured Error Responses5.2 Escalation and Ambiguity Resolution

    Evaluation (eval)

    A repeatable test of a model, prompt or agent against a set of cases with expected outcomes, scored by code, by people or by a model. Used to compare versions and catch regressions.

    Also: eval, evals, evaluation, evaluations

    Lesson 3.1 CLAUDE.md Hierarchy and Organization

    Exponential backoff

    Waiting longer after each failed attempt before retrying, usually with some random jitter, so retries do not overload the service.

    Also: backoff, retry with backoff

    Lesson 5.3 Error Propagation Across Agents

    Extended thinking

    A mode in which Claude reasons step by step in thinking blocks before giving its final answer, within a token budget. It helps on complex, multi-step problems at the cost of extra tokens and time.

    Also: thinking budget, thinking blocks

    Lesson 4.6 Multi-Instance and Multi-Pass Review

    F

    Few-shot prompting

    Putting a few worked examples of input and desired output in the prompt so the model follows their format and judgment. The examples should vary, or the model copies their surface details.

    Also: few-shot, multishot, few-shot examples

    Lessons 1.4 Workflow Enforcement and Human Handoff1.5 Agent SDK Hooks: Interception and Normalization4.2 Few-Shot Prompting for Consistency

    G

    Git worktree

    A second working directory on its own branch of the same repository, so several Claude Code sessions can work in parallel without touching each other's files.

    Also: worktree, worktrees

    Lesson 1.7 Sessions: Resume, Fork or Start Fresh

    Guardrail

    A check outside the model's own judgment that blocks or corrects unsafe or invalid actions, such as input validation, an allow list or a hook.

    Also: guardrails

    Lesson 1.5 Agent SDK Hooks: Interception and Normalization

    H

    Hallucination

    A confident statement that is not supported by the source material or by fact. Reduced by grounding answers in supplied documents, asking for quotes or citations, and allowing the answer "I don't know".

    Also: hallucinate, hallucinated

    Lesson 4.2 Few-Shot Prompting for Consistency

    Handoff

    Passing a task, together with the context needed to continue it, from one agent to another or from an agent to a person.

    Also: handoffs, hand off

    Lessons 1.4 Workflow Enforcement and Human Handoff1.5 Agent SDK Hooks: Interception and Normalization2.2 Structured Error Responses

    Headless mode

    Running Claude Code without the interactive session, using the -p flag, for scripts and CI pipelines. Output can be plain text or JSON.

    Lesson 3.6 Claude Code in CI/CD Pipelines

    Hook

    A command that runs automatically at a set point in an agent's lifecycle, for example before a tool call (PreToolUse) or after it (PostToolUse). Unlike an instruction in a prompt, a hook always runs.

    Also: hooks, PreToolUse, PostToolUse

    Lessons 1.4 Workflow Enforcement and Human Handoff1.5 Agent SDK Hooks: Interception and Normalization3.1 CLAUDE.md Hierarchy and Organization

    Human in the loop (HITL)

    A design in which a person reviews or approves certain actions or outputs before they take effect, usually the high-impact or low-confidence ones.

    Also: human-in-the-loop, HITL, human review, human approval

    Lessons 4.4 Validation, Retry and Feedback Loops5.5 Human Review and Confidence Calibration

    I

    Input schema

    The JSON Schema in a tool definition that names the tool's parameters, their types and which of them are required.

    Also: input_schema

    Lesson 4.3 Structured Output with Tool Use and JSON Schemas

    Iteration

    Improving a prompt or an output over several rounds, changing one thing at a time and checking the effect of each change.

    Also: iterate, iterating, iterative

    Lessons 1.1 The Agentic Loop and stop_reason1.2 Coordinator-Subagent Orchestration3.5 Iterative Refinement Techniques

    L

    Latency

    The time between sending a request and getting the response. For chat, the time to the first token matters most.

    Also: time to first token, TTFT

    Lessons 4.5 Batch Processing Strategies5.2 Escalation and Ambiguity Resolution

    M

    MCP resource

    Read-only data that an MCP server offers by URI, such as a file or a record, for the application to load into context.

    Also: MCP resources

    Lesson 2.4 Integrating MCP Servers

    MCP server

    A program that offers tools, resources or prompts over MCP, for example in front of a database, a file system or a business application.

    Also: MCP servers

    Lessons 1.1 The Agentic Loop and stop_reason2.4 Integrating MCP Servers

    Message Batches API

    An API for submitting large groups of requests that are processed asynchronously, usually within 24 hours, at half the normal price. Suited to work that does not need an answer straight away.

    Also: Batch API, batch processing, Message Batches

    Lesson 4.5 Batch Processing Strategies

    Messages API

    The main Claude API: you send a conversation as a list of user and assistant messages, plus optional system prompt and tools, and receive the next assistant message.

    Lessons 1.1 The Agentic Loop and stop_reason4.5 Batch Processing Strategies

    Model Context Protocol (MCP)

    An open standard for connecting AI applications to tools and data. An MCP server offers tools, resources and prompts; an MCP client inside the application connects to it.

    Also: MCP

    Lessons 1.1 The Agentic Loop and stop_reason2.2 Structured Error Responses2.4 Integrating MCP Servers

    Multi-agent system

    Several agents, usually an orchestrator and specialized subagents, working on one task. It gains parallel work and separate contexts at the cost of more tokens and coordination.

    Also: multi-agent

    Lessons 1.2 Coordinator-Subagent Orchestration2.2 Structured Error Responses5.3 Error Propagation Across Agents

    O

    Observability

    Being able to see what a system is doing from its traces, logs and metrics, such as each model call, tool call, delay and cost in an agent run.

    Also: tracing, traces

    Lessons 1.2 Coordinator-Subagent Orchestration2.5 Choosing the Right Built-in Tool3.4 Plan Mode versus Direct Execution

    Orchestrator

    The agent or code that splits a task, hands the parts to workers or subagents and combines what they return.

    Also: coordinator, lead agent, orchestrator-workers

    Lessons 1.2 Coordinator-Subagent Orchestration1.3 Spawning Subagents and Passing Context5.3 Error Propagation Across Agents

    P

    Plan mode

    A Claude Code mode in which Claude explores the code and proposes a plan without editing files, so you can review the approach before any change is made.

    Lessons 3.4 Plan Mode versus Direct Execution3.5 Iterative Refinement Techniques

    Precision and recall

    Precision is the share of flagged items that really are positive; recall is the share of real positives that were flagged. Raising one usually lowers the other.

    Lesson 4.1 Explicit Criteria and False Positives

    Prompt chaining

    Splitting a task into a sequence of prompts in which each step's output feeds the next, so every step stays simple and can be checked on its own.

    Also: chained prompts

    Lesson 1.6 Task Decomposition Strategies

    Prompt injection

    An attack in which instructions hidden in content the model reads, such as a web page, email, document or tool result, try to make it act against its user or developer.

    Also: indirect prompt injection, injection

    Lessons 2.1 Tool Descriptions and Boundaries4.1 Explicit Criteria and False Positives

    Prompt template

    A reusable prompt with fixed instructions and placeholders for the parts that change, so a team gets consistent results from the same kind of request.

    Also: prompt templates, template, templates

    Lessons 1.2 Coordinator-Subagent Orchestration1.4 Workflow Enforcement and Human Handoff1.7 Sessions: Resume, Fork or Start Fresh

    R

    Rate limit

    A cap on requests or tokens per minute for an organization. Going over it returns HTTP 429, which a client should handle by waiting and retrying with backoff.

    Also: rate limits, HTTP 429, 429

    Lesson 5.3 Error Propagation Across Agents

    S

    Skill

    A folder with a SKILL.md file of instructions, plus optional scripts and resources, that Claude loads only when a task needs it. Skills work in Claude Code, the API and claude.ai.

    Also: skills, Agent Skills, SKILL.md

    Lesson 3.2 Custom Slash Commands and Skills

    Slash command

    A command typed as /name in Claude Code. Built-in commands control the session; custom ones run saved prompts.

    Also: slash commands, custom command, custom commands

    Lesson 3.2 Custom Slash Commands and Skills

    Stop reason

    The field in an API response that says why generation ended, for example end_turn, max_tokens, stop_sequence or tool_use. An agent loop reads it to decide whether to run a tool or finish.

    Also: stop_reason, end_turn

    Lesson 1.1 The Agentic Loop and stop_reason

    Stratified sampling

    Sampling from each category, such as document type or risk level, so that rare but important cases are checked too.

    Also: stratified sample

    Lessons 4.5 Batch Processing Strategies5.5 Human Review and Confidence Calibration

    Structured outputs

    Constraining a response to a given JSON schema so code can parse it reliably. A tool with an input schema can be used the same way.

    Also: structured output

    Lessons 2.3 Distributing Tools and Configuring tool_choice3.6 Claude Code in CI/CD Pipelines4.3 Structured Output with Tool Use and JSON Schemas

    Subagent

    An agent started by another agent to handle one subtask in its own context window. It returns only its result, which keeps the parent's context small.

    Also: subagents, sub-agent

    Lessons 1.2 Coordinator-Subagent Orchestration1.3 Spawning Subagents and Passing Context2.3 Distributing Tools and Configuring tool_choice

    System prompt

    Instructions sent separately from the conversation that set Claude's role, rules and background for every turn of it.

    Also: system prompts

    Lessons 1.3 Spawning Subagents and Passing Context1.5 Agent SDK Hooks: Interception and Normalization2.1 Tool Descriptions and Boundaries

    T

    Temperature

    A sampling setting that controls randomness: lower values give more predictable wording, higher values more varied wording. It does not make answers more accurate.

    Lessons 1.4 Workflow Enforcement and Human Handoff1.5 Agent SDK Hooks: Interception and Normalization2.1 Tool Descriptions and Boundaries

    Token

    The unit models read and write text in, on average a little less than one English word. Context windows, rate limits and prices are all counted in tokens.

    Also: tokens

    Lessons 1.1 The Agentic Loop and stop_reason1.2 Coordinator-Subagent Orchestration2.4 Integrating MCP Servers

    Tool description

    The text in a tool definition that says what the tool does, when to use it and what its inputs mean. Claude picks tools mainly from these descriptions, so vague or overlapping ones cause wrong choices.

    Also: tool descriptions

    Lessons 1.5 Agent SDK Hooks: Interception and Normalization2.1 Tool Descriptions and Boundaries

    Tool result

    The message that returns a tool's output to Claude, matched to the request by its ID. Marking it as an error lets Claude see that the call failed and recover.

    Also: tool_result, is_error

    Lessons 1.1 The Agentic Loop and stop_reason1.7 Sessions: Resume, Fork or Start Fresh5.1 Preserving Facts in Long Conversations

    Tool use

    Letting Claude call functions you define. Claude returns a tool_use request with arguments, your code runs the tool, and you send the output back as a tool result.

    Also: function calling, tool call, tool calls, tool calling

    Lessons 1.1 The Agentic Loop and stop_reason1.3 Spawning Subagents and Passing Context4.3 Structured Output with Tool Use and JSON Schemas

    tool_choice

    An API setting that lets Claude decide whether to use a tool (auto), requires it to use one (any), forces a named tool, or turns tools off (none).

    Lessons 2.3 Distributing Tools and Configuring tool_choice4.3 Structured Output with Tool Use and JSON Schemas

    V

    Verification

    Checking AI output against a trusted reference before it is used, such as the source documents, known data or an expert, with more checking where the stakes are higher.

    Also: verify, verified, fact-check, fact-checking

    Lessons 1.4 Workflow Enforcement and Human Handoff1.5 Agent SDK Hooks: Interception and Normalization3.5 Iterative Refinement Techniques
